# Java 21 기술 선택 결정서

## 1. 결정

본 프로젝트는 Java 21 LTS를 기준으로 구현합니다.

수업의 핵심 요구사항인 JDBC, DAO/DTO, MySQL CRUD 구현은 Java 표준 JDBC 방식으로 충실히 구현하고, Java 21은 향후 AI 서비스 서버 확장 가능성을 고려한 기반 기술로 선택합니다.

## 2. 배경

프로젝트 주제는 카페 주문 데이터 관리입니다. 현재 단계에서는 콘솔 기반 CRUD가 중심이지만, 프로젝트 도메인을 AI 서비스 관점으로 확장하면 다음 작업이 자연스럽게 연결됩니다.

```text
주문 데이터 저장
-> 주문 패턴 분석
-> 인기 메뉴 추천
-> AI 챗봇 주문 보조
-> 외부 AI API 호출
-> 다중 요청 처리
```

이 흐름에서는 DB I/O와 외부 API 호출처럼 기다리는 시간이 많은 작업이 늘어납니다.

## 3. Java 21의 장점

| 항목 | 설명 |
| --- | --- |
| LTS | 장기 지원 버전이므로 학습용과 실무용 모두 설명 가능 |
| 가상 스레드 | I/O 중심 서버에서 많은 요청을 효율적으로 처리 가능 |
| 현대 Java 문법 | `record`, 향상된 switch, text block 등을 활용 가능 |
| 서버 확장성 | 향후 AI API 연동, 멀티 에이전트 서버 구조로 확장 가능 |

## 4. 가상 스레드 적용 입장

현재 JDBC 콘솔 CRUD 자체에 가상 스레드가 반드시 필요한 것은 아닙니다.

따라서 본 프로젝트의 기본 구현은 다음 원칙을 따릅니다.

```text
1. JDBC CRUD는 정석적인 DAO 구조로 구현한다.
2. Connection 객체 관리와 자원 반환을 명확히 처리한다.
3. 가상 스레드는 향후 AI 서버 확장 가능성 또는 비교 실험으로 설명한다.
```

이 접근은 기술 과시가 아니라 단계적 확장 설계입니다.

## 5. 발표 답변 예시

질문:

```text
왜 Java 17이 아니라 Java 21을 사용했나요?
```

답변:

```text
Java 21은 LTS 버전이며, 본 프로젝트의 핵심인 JDBC, DAO/DTO, MySQL CRUD 구현에는 Java 표준 방식을 그대로 사용했습니다.
다만 프로젝트를 향후 AI 서비스 서버로 확장할 경우 외부 API 호출과 DB I/O가 많아질 수 있어,
가상 스레드 등 Java 21의 기능을 고려한 확장 가능한 기반으로 선택했습니다.
```

질문:

```text
가상 스레드가 이 프로젝트에 꼭 필요한가요?
```

답변:

```text
현재 콘솔 CRUD 단계에서는 필수는 아닙니다.
그래서 기본 구현은 JDBC와 DAO 구조를 중심으로 작성합니다.
다만 AI 서버로 확장하면 다중 요청, DB I/O, 외부 API 호출이 많아지므로 Java 21의 가상 스레드가 의미 있는 선택이 됩니다.
```

질문:

```text
수업 범위를 벗어난 것 아닌가요?
```

답변:

```text
수업 핵심 요구사항인 JDBC, DAO/DTO, MySQL CRUD를 먼저 충실히 구현했습니다.
Java 21은 이 요구사항을 대체하는 기술이 아니라, 같은 요구사항을 최신 LTS 환경에서 구현하기 위한 기반 선택입니다.
```

## 6. 결론

Java 21 선택은 프로젝트의 핵심 요구사항을 흐리는 선택이 아니라, 수업 요구사항을 만족하면서 AI 서비스 서버 확장 가능성을 열어두는 기술 결정입니다.
