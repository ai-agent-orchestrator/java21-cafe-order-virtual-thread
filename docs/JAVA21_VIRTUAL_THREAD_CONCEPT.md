# Java 21 가상 스레드 개념 및 사용 이유

## 1. 학습 방향

본 프로젝트에서는 Java 21 가상 스레드를 성능 튜닝 기술로 깊게 다루기보다, Java 21 백엔드에서 I/O 중심 작업을 어떻게 더 가볍게 처리할 수 있는지 이해하는 데 초점을 둔다.

기존 카페 주문 관리 시스템에 JDBC/MySQL 데이터 연동을 적용하면, 주문 등록이나 조회 과정에서 DB 응답을 기다리는 시간이 발생할 수 있다.

이러한 DB I/O 대기 작업이 여러 개 동시에 발생한다고 가정하면, Java 21 가상 스레드가 어떤 흐름으로 작업을 처리하는지 실험해볼 수 있다.

## 2. Stack / Heap 요리 비유

수업에서 배운 Stack과 Heap을 요리로 비유하면 다음과 같이 이해할 수 있다.

```text
Stack = 지금 요리 중인 작업대
Heap = 객체를 보관하는 음식 창고
```

Stack에는 현재 실행 중인 메소드, 지역 변수, 실행 흐름처럼 지금 처리 중인 정보가 올라간다.

Heap에는 `new`로 생성된 객체처럼 여러 곳에서 참조될 수 있는 데이터가 저장된다.

## 3. Platform Thread 방식

기존 플랫폼 스레드 방식은 요리사가 재료가 올 때까지 작업대를 계속 차지하는 방식으로 이해할 수 있다.

DB 응답을 기다리는 동안 실제로 계산을 하고 있지 않아도, 작업대에 해당하는 Stack과 OS Thread는 계속 묶여 있을 수 있다.

```text
Platform Thread
재료를 기다리는 동안에도 작업대(Stack)를 계속 차지
```

## 4. Virtual Thread 방식

Java 21의 가상 스레드는 주문표처럼 많이 만들 수 있는 가벼운 스레드로 이해할 수 있다.

가상 스레드는 재료를 기다리는 주문의 상태를 잠시 창고에 보관해두고, 작업대(Stack)는 다음 주문을 처리하는 데 사용하는 방식으로 이해할 수 있다.

```text
Virtual Thread
기다리는 주문 상태는 JVM이 관리
작업대(Stack)는 다음 주문 처리
```

여기서 중요한 점은 가상 스레드가 DB 자체를 빠르게 만드는 기술은 아니라는 것이다.

가상 스레드는 DB I/O나 외부 API 호출처럼 기다리는 시간이 많은 동시 작업을 더 가볍게 다루기 위한 실행 모델이다.

## 5. JDBC/MySQL 프로젝트와의 연결

본 프로젝트는 JDBC와 MySQL을 사용한다.

주문을 등록하거나 조회할 때 Java 코드가 MySQL에 요청을 보내고, DB 응답을 기다리는 시간이 발생할 수 있다.

이런 I/O 대기 작업에서는 스레드가 계속 OS Thread를 붙잡고 있으면 비효율적일 수 있다.

Java 21 가상 스레드는 대기 중인 작업의 실행 상태를 관리하고, Carrier Thread를 다른 작업에 사용할 수 있게 하므로 I/O 중심 백엔드 구조를 이해하는 데 의미가 있다.

## 6. 실험 구현 목표

본 프로젝트에서는 Java 21 가상 스레드를 단순 실행 예제로 사용하지 않는다.

JDBC/MySQL 주문 처리 과정의 I/O 대기 구간과 연결하여 다음 정보를 기록하는 방식으로 실험한다.

```text
- 실행한 작업 이름
- 실행한 스레드 이름
- 스레드 타입
- 작업 시작 시점
- DB I/O 대기 시작 시점
- DB I/O 대기 종료 시점
- 작업 종료 시점
- 대기 시간
- 전체 실행 시간
- 실행 결과
```

이를 통해 여러 주문 처리 작업이 Virtual Thread로 실행될 때, I/O 대기 구간을 어떤 흐름으로 지나가는지 콘솔 로그와 DB 기록으로 확인한다.

## 7. 발표용 핵심 문장

```text
Java 21 가상 스레드를 단순 실행 예제로 사용한 것이 아니라,
JDBC/MySQL 주문 처리 과정의 I/O 대기 구간과 연결하여
스레드 이름, 작업 시작 시점, 대기 시작/종료 시점, 전체 실행 시간을 기록하는 방식으로 실험했습니다.
```

```text
가상 스레드를 이해한다는 것은 Thread.ofVirtual()을 호출하는 것이 아니라,
I/O 대기 구간이 있는 여러 작업의 실행 흐름을 직접 관찰하고 설명할 수 있다는 뜻입니다.
```
